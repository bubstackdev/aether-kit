# MiniMax H3 integration

Aether owns H3 export and application orchestration. Corsairs owns checked tensors, native execution, resource ownership and runtime qualification. The runtime dependency is pinned to the published crates.io `0.3.0` release. Nothing in this integration modifies Corsairs, the Atelier lab or the original checkpoint.

Profiles must declare `transformer_weight_layout: "raw_per_head_qkv_to_contiguous_qkv_v1"`. Earlier Aether exports missed the raw-checkpoint normalization that precedes the original transformer's key converter; they must be re-exported. [Correction and current validation](h3-turbo.md). The original fifty-step schedule remains available with corrected weights; historical gates on earlier weights are retained with their limited scope.

`H3Pipeline` implements `AudioVideoPipeline` for text-to-audio/video. The default `base50` recipe executes the original 50-layer unnormalized Qwen tap, the input projections and two text-refiner layers, all 50 original BF16/F32 transformer blocks at all 50 base schedule pairs, final normalization/output heads, and both F32 decoders. The separate `turbo8` recipe preserves dynamic low-rank adapter branches and uses its pinned eight-evaluation schedule. Dense joint attention includes all audio/video/text rows. There is one joint evaluation per step and no unconditional branch. [Turbo native result and validation scope](h3-turbo.md): a usable visual pilot with audio completes in 11m 48s including its numerical gate.

```rust,no_run
use aether::{AudioVideoPipeline, AudioVideoRequest, ImageSize};
use aether::h3::{H3Assets, H3Options, H3Pipeline};
use std::path::Path;

async fn render() -> aether::Result<()> {
    let assets = H3Assets::open("/path/to/profile/bundle.json")?;
    let mut pipeline = H3Pipeline::new(assets, H3Options::default())?;
    let request = AudioVideoRequest::new(
        "integrated_multimodal_description: ...\n\noverall_soundscape: ...\n\nnon_diegetic_music: ...",
        ImageSize::new(960, 544), 124, 1043,
    );
    let clip = pipeline.generate(&request, Path::new("clip" )).await?;
    clip.mux_mp4("/opt/homebrew/bin/ffmpeg", "clip.mp4")?;
    pipeline.unload().await
}
```

The initial partition is FL2VA snapshot `42ed227ee7df40d41602854ae760620d6eb651fe`, with Diffusers commit `7ecb1e1b4fe500be7fb7381a7bb79a24d7fa3941`. Ref2VA is absent. The first generator supports T2VA; first/last-frame requests fail explicitly until Aether adds processor/vision and sampled VAE conditioning. Their captured row layouts already pass independent tests.

## Export in Aether

`forge/h3_export.py` is the offline recipe. It calls the lab's pinned, unmodified Diffusers/Transformers modules and converter, reads the existing checkpoint and verified explicit body-weight fixtures, and writes only beneath the selected output directory. It does not install dependencies or download weights. Python and Swift are absent from generation.

A profile currently fixes canvas, aligned frame count and prompt token count. Tokenization is the verbatim prompt with no chat template or added special tokens. A mismatched request fails before native execution. The diagnostic profile is deliberately explicit:

```sh
PYTHONDONTWRITEBYTECODE=1 /Users/zakkeown/Code/aether-engine/forge/.venv/bin/python -B \
  forge/h3_export.py --lab /Users/zakkeown/Code/atelier/lab/minimax-h3-lab \
  --output .local/h3-diagnostic --width 128 --height 128 --frames 22 --text-rows 49
```

Stages `front`, `modulations`, `conditioner`, `audio`, `video` and `finalize` can run separately and retain intermediate build records. `--reuse PROFILE/build.json` reuses geometry-independent modulation assets and a conditioner with the same text length. `decoders` runs audio, video and finalization. Full profile exports occupy tens of GB; body parameters remain external references to the existing 38.5 GB lab fixture set. All files must remain immutable during use.

Run a supplied original-condition/noise replay, then native prompt encoding:

```sh
cargo run --offline --release --example h3_generate -- \
  .local/h3-diagnostic/bundle.json .local/h3-provided-report.json \
  .local/h3-provided-clip --provided --diagnostic

cargo run --offline --release --example h3_generate -- \
  /path/to/production/bundle.json .local/h3-render-report.json .local/h3-render
```

The example takes an optional prompt string; otherwise it uses the saved oracle prompt from the profile. It writes a report and progress journal and retains raw decoder samples/latents for acceptance. `--prepare-only --provided` and `--encode-only` isolate the original CPU-oracle boundaries. Use a native execution environment permitted to access Core AI's model cache. Run one GPU job at a time.

`h3_benchmark BUNDLE.json REPORT.json 5` measures the first five real denoising steps and then both full-profile decoders, with no media artifact or quality claim. It prepares every modulation plan in the bundle's recipe and preserves that complete source schedule. `benchmark_with` shares the generation implementation; its prefix length cannot change ordinary `generate` behavior. Timing events separate integrity, conditioning, modulation, upload/setup, body graph loading, all body blocks, heads, host updates and decoder windows. Decoder timing includes readback, finite checks and temporal stitching/hashing; PNG/WAV encoding and MP4 mux are excluded. `scripts/run-h3-benchmark.py` owns one child with an explicit deadline and preserves its exit independently of an observation connection.

## Numerical and residency contracts

Actual T2VA has one distinct timestep on its first call and two thereafter. Aether deduplicates/sorts actual row times and preserves their exact AdaLN row mapping; it does not reuse synthetic three-timestep caches. Each original constant-weight projection is evaluated for all actual schedule pairs before body acquisition. `H3Options::preparation_cache` optionally persists completed native time embeddings and modulation tables. Its key covers time/modulation source hashes and function names, adapter identity, recipe, complete schedule and exact input timestep bits. Loads check tensor hashes, dimensions and dtypes; corrupted entries fail explicitly. The application owns this trusted directory and keeps published entries immutable. The prompt cache remains a two-entry in-process LRU. Native cache-hit equality is pending. Experimental dynamic AdaLN projection, quantization, approximation and layer dropping are absent.

The source scheduler predicts data-ward velocity: it builds x0 from the float32 timestep, then blends with the independent sigma-grid ratio. Separate float32 operations match all 50 upstream oracle hashes. This differs from Krea's Euler update. Aether seeds one SplitMix64/Box–Muller stream for contiguous video latents followed by channel-major stereo audio; exact PyTorch replay supplies original latent rows via `generate_conditioned`.

The conditioner acquires/releases one layer at a time and bypasses final normalization. A two-entry prompt cache stores small encoded features. Before denoising, body parameters are hash-checked and uploaded directly into persistent shared Metal buffers. One fixed operator graph per actual timestep cardinality uses two distinct hidden buffers. After denoising, all functions/buffers are dropped and `Runtime::drain()` completes before decoder acquisition. Drain does not promise OS page eviction. Full model stream hashes are verified once per pipeline; tensor fixture hashes are checked on upload.

The video VAE uses its original seven-latent windows at stride five. Each window decodes 22 frames; Aether emits 17, retains the last five, and cross-fades with the next window exactly as the source does. Spatial tiling and noncausal attention remain inside the original decoder graph. Stitching happens before ImageNet denormalization and RGB8 rounding. Native output delivery is bounded by a window, without changing context boundaries. CPU tests compare the complete 124-frame stitching result byte for byte with the original VAE control flow using a deterministic decoder stub; original-weight decoder inference is checked separately.

`retain_decoded` saves unclipped float32 video in FCHW order and planar stereo audio, with shapes/layouts in `decoded.json`. Final latents are also retained. Normal output is incremental PNG frames plus IEEE float WAV; optional explicit FFmpeg mux preserves those sources and refuses overwrite. MP4 is lossy and cannot serve as the numerical oracle.
