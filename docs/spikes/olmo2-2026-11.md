# v0.0.6 spike: OLMo 2 1B Instruct

**Result: port implemented and native integration passes.** The selected checkpoint is
[`allenai/OLMo-2-0425-1B-Instruct`](https://huggingface.co/allenai/OLMo-2-0425-1B-Instruct/tree/48d788eca847d4d7548f375ad03d3c9312f6139e),
revision `48d788eca847d4d7548f375ad03d3c9312f6139e`, Apache-2.0. Work lives on
`spike/v0.0.6-olmo2` in `.worktrees/v006-olmo2`. This is a v0.0.6 spike candidate,
not a change to the published release's qualified-model list.

## Why this model

Aether's existing text exports implement Qwen3-style pre-normalized blocks and
per-head Q/K RMSNorm. OLMo2 needs full-projection Q/K RMSNorm **before splitting
heads**, and normalizes the attention output and MLP output **before adding each
residual**. Reusing Qwen3's placement would give the wrong model even though
all tensor shapes fit. The 1B checkpoint makes real-weight experiments practical.
The upstream implementation is Transformers 4.57.3's
[`modeling_olmo2.py`](https://github.com/huggingface/transformers/blob/v4.57.3/src/transformers/models/olmo2/modeling_olmo2.py).

## Architecture gained

`Forge/language/dense_decode.py` owns RMSNorm/RoPE primitives, attention/cache
execution, both step contracts, host cache updates, export examples, and mapped
checkpoint loading. A family supplies a block's `project` and `finish` methods
and its checkpoint tensor map. `olmo2_decode.py` implements OLMo2's normalization
and residual layout; `qwen3_decode.py` keeps Qwen3's layout.

`export_dense.py`, `reference_dense.py`, and `register_dense_bundle.py` share the
conversion, independent oracle, self-checks, hashing, tokenizer copying, and
registration. The original Qwen3 command/import entry points remain available;
OLMo2 has matching export/reference entry points. A future compatible dense
family can reuse this machinery without duplicating the cache loop. Sliding
attention, scaled RoPE, biased attention, recurrent state, and MoE remain outside
this seam. Unsupported OLMo2 model types, activations, biases, and RoPE scaling
are refused.

The Swift runtime and manifest format already support the exported contract.
No new runtime API or dependency is needed. The native qualifier now derives its
fixed-length decode sentinel from the reference vocabulary instead of Qwen's
hardcoded padding token. The chosen final vocabulary row must be unused padding;
this is true of the checkpoints used here. Registered bundle sessions use the
checkpoint's actual EOS, `100257`.

## Qwen3 mismatch RCA and fix

The unchanged baseline (`6b20db1`) and the shared-code version produced identical
failing `--tiny` checks with float16 attention. On the first prediction, eager
selected token 211 and Core AI CPU selected 398. Float32 evaluation of the same
stored weights gave logits 2.06082821 and 2.05759192, only 0.00323629 apart.
Native fp16 logits were 2.056640625 and 2.06640625, reversing their order.
No cache rows were lost, and the remaining four predictions agreed.

An isolated causal GQA SDPA experiment narrowed this to an attention precision
difference: Core AI CPU fp16 SDPA differed from a float32-accumulating reference
by up to 0.003662109375; explicitly float32 SDPA matched the probe exactly after
casting its output back to fp16. This establishes observable operator behavior,
not the proprietary runtime's internal accumulation algorithm.

New dense exports explicitly promote Q/K/V to float32 for SDPA, then cast the
attention result back to the original dtype. Cache updates and weights remain
fp16. The original failing row now selects token 211 in both eager and native,
and both families pass every strict self-check row. **The acceptance threshold
and exact-argmax requirement were not relaxed.** `test_dense_export.py` asserts
that specific prediction as a regression. Existing compiled models are not
modified; re-export to get the fix. The legacy arithmetic remains selectable
with `--attention-precision float16`; Qwen3-VL's directly constructed blocks keep
their previously qualified execution path.

Reproduce the isolated operator experiment with:

```sh
Forge/.venv/bin/python -I Spikes/olmo2/probe_sdpa.py --output /absolute/new-sdpa-output
```

## Use and reproduce

This worktree contains a ready-to-use registered bundle at
`.local/olmo2/bundle` (ignored by Git). The independent reference and binary logits
are at `.local/olmo2/reference`. The exporter report records the original
checkpoint location under `/private/tmp/aether-v006-olmo2/checkpoint`; that source
checkpoint is not needed for inference.

```swift
import AetherLanguage
import Foundation

let model = AetherLanguageModel(bundle: URL(filePath: "/absolute/worktree/.local/olmo2/bundle"))
let session = AetherLanguageSession(model: model)
let reply = try await session.respond(to: "Explain why the sky is blue.")
print(reply.content)
```

To reproduce from local files, install Forge's locked environment with
`uv sync --frozen --project Forge`, obtain the pinned checkpoint above, then run:

```sh
sh Spikes/olmo2/qualify.sh /absolute/checkpoint /absolute/new-output
sh Scripts/check-cpu.sh
```

`AETHER_FORGE_PYTHON` can select an existing matching Forge environment. The script
runs weight-free differential/Core AI regressions, an independent upstream
float32 reference, conversion, registration, tokenizer parity, native decoding,
chat, and facade gates. It downloads nothing and takes Aether's shared GPU lease
for native tests. Model assets keep their own license; no assets are committed.
