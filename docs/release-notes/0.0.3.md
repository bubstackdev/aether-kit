# AetherKit 0.0.3 — experimental developer preview

Released YYYY-MM-DD.

0.0.3 adds an app-facing language product:
- `AetherLanguage`, a text facade in FoundationModels' shape, with sampling, streaming and structured output into
  `Decodable` types (`@AetherGenerable`);
- an adapter that lets FoundationModels' `LanguageModelSession` run a Kit model.

The package floor drops to macOS 14 and iOS 17, so apps can link the facade there; it reports "unsupported OS" below 27.
0.0.3 also clears most of the 0.0.2 backlog:
- **Qwen3-VL:** the decoder wires its weights once, and prompts can carry several images.
- **Language:** sessions take resource admission, and long prompts reach their first token about twice as fast.
- **H3:** it sheds its second denoiser specialization, passes session lifecycle and media audits and the user's audio
  and video review, and is **promoted from Experimental to Preview**.
- **FLUX.2:** cancellation is qualified natively for both encoders, and there's a quiet-window benchmark.
- **iPhone:** a second iPhone runs Kokoro through bucket 512 and the Qwen3-0.6B.
- **Spikes:** four reach go/no-go decisions.

Every model is still checked against independent references computed on the CPU. **There is still no API
compatibility promise in 0.0.x, and no model weights are distributed.**

## Install

```swift
.package(url: "https://github.com/bubstackdev/aether-kit", exact: "0.0.3")
```

See the [README](../../README.md) for the quick starts, and the [deployment floor](../deployment-floor.md) for what links
and what runs below macOS 27.

## Highlights

- **App-facing language product:**
  - **Availability first.** `AetherLanguageModel(bundle:)` reports `unsupportedOS`, `unsupportedPlatform`,
    `bundleMissing`, `bundleInvalid` or `unsupportedTemplate` without hashing or loading.
  - **Loading and generation.** The model loads lazily, fully verified, on `prewarm()` or the first request. Greedy
    is the default; seeded sampling, the repetition penalty, stop sequences and reasoning are set per request.
  - **Structured output.** `respond(to:generating:)` runs a JSON-schema constraint beside each decode step, which
    averages under 0.1 ms per call. The schema subset is what FoundationModels' `@Generable` emits; anything else is
    refused rather than run unconstrained.
  - **The adapter.** An app can keep `LanguageModelSession` and pass `model: AetherLanguageModel(bundle:)`.
- **Package floor: macOS 14 / iOS 17.** Every Core AI declaration is `@available(macOS 27, iOS 27, *)`, and CoreAI and
  FoundationModels link weakly. CI launches a floor consumer on macOS 14. Tests need the 27 triple
  (`swift test --triple arm64-apple-macosx27.0`); the check scripts pass it.
- **Language:**
  - **Long prompts.** A bucketed prompt longer than 256 tokens now gets its KV cache sized up front and prefills in
    256-token chunks. Warm time to first token at 2,048 tokens falls from 365–371 to 147–155 ms on the Qwen3-0.6B, and
    from 949–973 to 489–533 ms on the 4B writer. Prompts of up to 256 tokens keep the 0.0.2 plan.
  - **Host copies.** Bucketed cache growth and step updates copy less on the host, with identical bytes.
- **Qwen3-VL:**
  - **One decoder function.** The re-exported VL-4B wires 8.2 GiB of mapped-file pages for an image request instead of
    15.7 GiB (8,414 against 16,086 MiB). Its compiled cache is 15.0 GiB instead of 22.5 GiB.
  - **Several images per prompt,** qualified on the VL-2B and VL-4B. EXIF-rotated photos give the unrotated photos'
    results exactly.
  - **Sampling and constraints** on the image path.
  - **Resource admission.** Opening waits for a GPU grant under `gpu:`, and `LanguageResourceAdmission` reserves measured
    residency and scratch. A guarded VL-4B plus Krea 1024² run completed with the describer inside its reservation.
- **H3:**
  - **Memory.** `H3ModulationPadding` keeps one modulation shape per render, so steady denoising at 960×544 falls from
    13.49 to 10.93 GiB (T2VA) and from 13.80 to 11.17 GiB (FL2VA), and video decode from 11.07 to 8.16 GiB. Both
    captures replay all 457 hashes.
  - **Admission.** Measured admission's worst case is 16.56 GiB, under the 18 GiB bar. It covers an unexplained step-0
    transient seen in two padded renders.
  - **Qualification.** Session lifecycle passes 49/49, and the media audit passes on the 960×544 Turbo8 renders.
  - **Timing.** The quiet-host reference is about 358 s of stage time for T2VA and 343 s for FL2VA (960×544×124,
    Turbo8).
- **FLUX.2:**
  - **New identities.** Hashing the chat template gives the same bundle bytes the fingerprint `d27cefc4…` (it was
    `a48aaf07…`).
  - **Cancellation.** A cancel returns in about 0.17 s during the text encoder's call. It waits for an in-flight function
    load, up to about 0.9 s (about 3.8 s on a process's first request). The reference encoder takes 0.18–0.21 s.
  - **Adherence.** Under a local Qwen3-VL judge, Kit and the float32 reference both answer 38/38.
  - **Benchmark.** In the quiet window, with balanced residency, a 512² image took 2.58–2.95 s encoded and
    1.03–1.50 s with provided conditioning, and a 1024² image 5.75 s and 4.42 s. Every iteration was exact.
- **iPhone:** an iPhone18,2 (iOS 27.2) runs:
  - Kokoro through bucket 512, including the new bucket-512 case;
  - the Qwen3-0.6B, at a time to first token of 0.037 s for a 33-token prompt.

## Core AI workarounds

These work around Core AI behaviour; they don't fix it, and each goes once Core AI changes.
- **Memory retained on shape changes** (from 0.0.2): language sessions reload the model once a 2 GiB growth budget
  is spent ([native memory retention](../language-generation.md#native-memory-retention)).
- **H3 modulation padding:** keeps one shape per render, so the second specialization never forms.
- **`SerialComputeStream`:** Core AI's `ComputeStream` has no concurrency annotation, so one `@unchecked Sendable` type
  now owns encoding and joining.

## Core AI defects observed on macOS 27.0.1 (26A434), under re-check

The 0.0.3 work recorded several Core AI behaviours that look like defects. A follow-up investigation is re-checking each
one, and some have already turned out to be caused by Kit's own exports. None is presented here as a confirmed Apple bug.
The reports:
- **Retention on input-shape changes:** [native memory retention](../language-generation.md#native-memory-retention).
- **`torch.cond` / `if_`:** the GPU compile doesn't finish and cpu_only aborts
  ([split-attention report](../spikes/split-attention-2026-10.md)).
- **Hybrid recurrent-state graphs:**
  - the dynamic contracts failed as exported, because their positions input carried q a second time;
  - cpu_only mask and state failures.

  See the [hybrid-state report](../spikes/hybrid-state-0.0.3.md#core-ai-defects-and-apple-feedback-candidates).
- **TripoSR:** an `einsum` grid function exported with wrong values ([TripoSR report](../spikes/triposr-2026-10.md)).
- **Kokoro:** the float16-compute decoder aborts when its float16 regions run on the Neural Engine, on macOS 27.0.1 and
  iOS 27.2 ([reduced-precision decoders](../kokoro-speech.md#reduced-precision-decoders),
  [iPhone](../kokoro-speech.md#iphone)).

## Known limitations

- **One qualified Mac.** On iOS, only Kokoro (two iPhones) and the Qwen3-0.6B (one iPhone) are qualified.
- **Below macOS 27, the facade runs nothing.** It reports `.unsupportedOS`. An optional MLX backend for older OSes is
  planned for 0.0.4.
- **No hosted assets,** download transport or preparation: apps hand the facade a bundle they installed themselves.
- **Language:** the memory budget is still a workaround for Core AI retention. Just above 256 tokens the wider prefill
  chunk retains about twice as much per request (the writer at 449 tokens: 58.6 to 109.8 MiB).
- **Qwen3-VL:**
  - Images stretch by up to about 15% to fit a grid.
  - Opening a decoder reads its whole compiled file into the page cache (15 GiB for the one-function 4B).
  - Resource admission is per process.
  - 0.0.2 two-function bundles still wire two weight copies and keep the 0.0.2 prefill plan.
  - **No iPhone run yet.**
    - At the default limits on an iPhone18,2, the VL-2B failed while opening: 4.29 GB of assets against 3,368 MiB
      available, with `mapped file 6.9G` in the crash report's VM summary, so the assets appear to be mapped more than once. It's attributed to virtual
      address-space exhaustion at default limits, not a jetsam kill.
    - The fix is planned for 0.0.4: the extended-virtual-addressing entitlement alongside the increased memory
      limit, and an open-time check that counts mapped bytes.
    - TBD: the run with the entitlement.
- **H3 (Preview):**
  - Measured admission knows one profile on one Mac (`5af39db5…`, Turbo8, M5 Max) and refuses others; Turbo4 stays
    outside it until its 0.0.4 qualification.
  - The admitted worst case carries an unexplained step-0 transient.
  - The qualified profile is a local export outside this repository; profile paths relative to `bundle.json` are a
    follow-up.
- **FLUX.2:**
  - Anything keyed on a 0.0.2 fingerprint, installation IDs included, needs the new one.
  - No iOS; it's planned for 0.0.4.
- **Kokoro:** phoneme input only; float32 decoder only.
- **GPU lease:** pid-less leases aren't reclaimed.
- **Real-weight qualification is local.** CI covers the weight-free suite, the floor build and launch, and the consumer
  packages.

## Compatibility

Expect source-breaking changes in any 0.0.x release. Coming from 0.0.2:
- `AetherVision` drops alpha by default; pass `.composite(red: 0, green: 0, blue: 0)` for 0.0.2's compositing.
- FLUX.2 fingerprints change.
- `Flux2Prompt.render(_:)` is removed.
- `AetherLanguageError` has two new cases.
- A bucketed prompt longer than 256 tokens uses the new prefill plan.
- Tests need the macOS 27 triple, and apps below macOS 27 call Core AI products behind `#available`.

0.0.2 language and Qwen3-VL bundles keep working.
