# AetherKit 0.0.5 — experimental developer preview

Released 2026-11-02.

0.0.5 is an H3 release with the codebase review's fixes, and it carries four v0.0.6 spikes early:
- **H3 FL2VA presents its keyframes as upstream does.** The known deviation found in 0.0.3 is fixed: each keyframe
  reaches the conditioner as a labelled vision block from Qwen3-VL's vision tower. The user chose the new presentation
  in an A/B review.
- **H3 last-frame and first+last keyframes.** A clip can end on a chosen picture, or start and end on chosen pictures.
  Qualified at 960×544 under the new presentation.
- **H3 measured admission for the final profile stack** (#81), keyed by a location-free identity: 5 s clips at
  960×544 and 544×960 under the 18 GiB bar, and 10 s clips and 1280×704 / 704×1280 under the 24 GiB bar on a 64 GiB
  Mac. Turbo4 is admitted too, at 960×544 and 544×960 for 5 s and 10 s clips, for memory only: it has no CPU
  trajectory gate.
- **The codebase review's fixes:** every finding still open on 0.0.4 is fixed, each with a regression test.
- **v0.0.6 spikes, merged early:** OLMo 2 1B Instruct, GPT-2 and Phi-2 through the language runtime, and SD-Turbo
  through a new spatial-diffusion seam. Each is an experimental macOS port. Kit now publishes converted bundles for
  OLMo2, GPT-2 and Phi-2 besides the Qwen3-0.6B sample.

The frozen API ([API stability](../api-stability.md)) is unchanged: the committed baseline in `api/` is the 0.0.4
baseline, and the **Public API (frozen)** check passes against it. **Outside the frozen API there is still no
compatibility promise in 0.0.x**, and 0.0.5 has H3 source changes ([below](#source-changes-and-migration)).

## Install

```swift
.package(url: "https://github.com/bubstackdev/aether-kit", exact: "0.0.5")
```

Building needs Xcode 27.2 (Swift 6.4). See the [README](../../README.md) for the quick starts and the
[H3 guide](../h3-integration.md) for keyframes and the presentation.

## Highlights

- **H3 FL2VA conditioner presentation** ([guide](../h3-integration.md#fl2va-conditioner-presentation-005)):
  - **As upstream.** Before the prompt, each keyframe (first, then last) gets its `"<Picture i>: "` label and a vision
    block from Qwen3-VL's vision tower, tagged as video, with M-RoPE positions and DeepStack after conditioner layers
    0–2. T2VA is unchanged. `H3Presentation` and `H3VisionInputs` reproduce upstream's ids, tags, positions, pixels and
    tables bit for bit.
  - **The profile.** `export-h3-profile.py --stage conditioner-vision` adds the tower as an overlay: one static graph
    per canvas, weights bound in place, each byte-identical to upstream on CPU. A profile without the overlay, which
    is every 0.0.4 profile, refuses FL2VA.
  - **Rows.** Each keyframe adds its presentation (518 rows at 960×544, 888 at 1280×704, 1,016 at 1344×768), so an
    FL2VA prompt has a smaller budget. `H3VideoSession` refuses a request that doesn't fit, before any stage runs,
    naming the rows or tokens.
  - **The bars, decided by the user on 2026-11-02.** The plan's first bars can't be met by any bf16 implementation:
    upstream's own bf16 tower is 0.033–0.075 from its fp32 computation. The bars are relative to the reference
    instead. The tower is held, per canvas and tensor, to at most 1.05× upstream's own bf16-vs-fp32 spread; the
    largest ratio measured is 1.03×. The conditioner, fed identical tower output, is held to 0.02 at decoder layers 0–3
    and on the tap's text rows; it measures 0.0028–0.0054 and 0.0080. Ids, tags, positions and pixels are exact.
  - **The user's A/B review.** On the same seed, prompt and keyframe, the old presentation turned the folded-paper
    crane into a realistic white bird, and the new one kept the keyframe's paper and facets. The user chose the new
    presentation, and confirmed the choice on a corrected render after a probe-only label bug was fixed
    ([record](../evidence/h3-fl2va-ab-2026-11-02.json)).
- **H3 last-frame and first+last keyframes**
  ([guide](../h3-integration.md#last-frame-and-firstlast-keyframes-2026-10-29)): `H3VideoRequest.lastFrame`, alone or
  with `firstFrame`, on the same FL2VA task, checkpoint, profile and step tables. Each keyframe is encoded by the same
  graphs and noised by its own draw in packed order, first then last; a first frame alone draws the same stream as
  before. In the 960×544 first+last render, the first frame matches the first keyframe at 31.9 dB PSNR and the last
  frame the last keyframe at 34.8 dB (text-only presentation).
- **The codebase review** ([review](../../CODEBASE-REVIEW.md)): every finding still open on 0.0.4 is fixed, each with a
  regression test, in the language schema compiler and JSON matcher, the `@AetherGenerable` macro, Kokoro, H3's
  admission and request checks, `aether-probe`, and the H3 qualification controllers. CI now runs the controllers'
  supervision tests (stub workloads, no GPU).
- **CI** ([CI](../ci.md)): every job builds with Xcode 27.2, the toolchain the consumers use, and the host check fails
  on any other Xcode. The macOS 15 launch without CoreAI no longer runs on pull requests, because GitHub's hosted
  `macos-15` queue held them 20–60+ minutes. It runs on every `main` push, and a release is tagged only on a `main`
  commit whose push run passed it: `sh Scripts/check-release-ci.sh <commit>` checks that.
- **v0.0.6 spikes, merged early.** Each is an experimental port qualified on the Mac only, against independent
  upstream references. None is in the frozen API or the qualified-model list.
  - **OLMo 2 1B Instruct** ([spike](../spikes/olmo2-2026-11.md)): post-sublayer normalization and full-projection Q/K
    norms through a shared dense exporter. The native decoder matches upstream float32 on 32/32 argmax rows, and a
    greedy 64-token continuation is identical. It chats through the language facade and the FoundationModels adapter.
  - **GPT-2** ([spike](../../Spikes/gpt2/README.md)): learned absolute positions, LayerNorm, biased projections and
    GELU. Completion only, through `LanguageGenerationSession`; the chat facade reports `unsupportedTemplate`. Native
    fp16 passes the language qualification policy; it isn't bit-exact with float32 generation (the short prompt first
    diverges at token 40).
  - **Phi-2** ([spike](../../Spikes/phi2/README.md)): partial rotary embeddings and parallel attention/MLP residuals,
    with float32 arithmetic over fp16 weights and caches. Completion only. Native GPU matches all 192 forced tokens and
    three 64-token continuations exactly. It needs 0.0.5's stride-aware caches.
  - **SD-Turbo** ([spike](../spikes/sd-turbo-2026-11.md)): the new `AetherDiffusion`, `AetherDiffusionCoreAI` and
    `AetherSDTurbo` products: an epsilon/Euler scheduler and session with stateless Core AI stages, and a local CLIP
    tokenizer. The whole native pipeline at 512×512 is within 0.000026 RMSE of the reference at one to four steps, and a
    repeat after release and reopen is exact. Float32 throughout (about 4.7 GiB of assets).
- **Published bundles.** Besides the Qwen3-0.6B sample, Kit now publishes three converted bundles, each a macOS bundle
  (`mac/`) with a ready catalog entry, its own LICENSE and NOTICE, and publication evidence of every hosted file's size
  and SHA-256. No iOS bundle is published for them, and the weights are not in this repository.

**Location-free profile identity.** Measured admission is keyed by `h3.profile/2:<H3Profile.contentSHA256>:<recipe>`.
`contentSHA256` hashes the profile manifest without its `path` fields, its tokenizer directory or `lineage`, with
sorted keys; every referenced file is still pinned by its own SHA-256. A profile copied to another path, Mac or user
keeps its identity and its measured entries, so an app that prepares its own copy of a profile is admitted on Kit's
entries. `aether-probe h3-profile-identity PROFILE.json [RECIPE]` prints a profile's identities (CPU only). The
bundled 0.0.3 entry is re-keyed to `0707647b…`, the content of 5af39db5 and of the c49d8dbf original.

## Source changes and migration

0.0.5 changes no frozen API. These H3 changes affect code outside it:
- **FL2VA needs the vision overlay.** A profile without `conditioner_vision` (every 0.0.4 profile) refuses FL2VA, as
  does a canvas without a tower graph; T2VA is unchanged. **Migration:** add the overlay with
  `Scripts/export-h3-profile.py --stage conditioner-vision`, which also gives the profile a new identity.
- **The conditioner returns `H3Conditioning`.** `H3PromptConditioner.encode(_:keyframes:geometry:onLayer:)` returns
  the tap and the row tags, and `H3Denoiser.denoise(_:conditioning:geometry:onStep:)` takes it. Both have default
  implementations for text-only conditioners, so existing conformances compile.
- **A smaller FL2VA prompt budget.** Each keyframe's presentation rows count against the profile's 4,096 text tokens
  and the 40,960 packed rows: 518 rows per 960×544 keyframe. Requests that no longer fit are refused before any stage
  runs; a 1280×704 × 141 first+last request and a 1344×768 × 124 first+last request can't fit at all
  ([table](../h3-integration.md#fl2va-conditioner-presentation-005)).
- **Hand-built latents declare their anchors.** A hand-built first-frame `H3Latents` needs `anchors: [.first]`; the
  denoiser no longer infers anchors from the row count, because a last-only request has a first-only request's rows.
- **Measured identities are `h3.profile/2`** (#81). `H3ProfileEngine.resourceIdentity` is now
  `h3.profile/2:<H3Profile.contentSHA256>:<recipe>`, so entries written with `h3.profile/1:` identities no longer
  match, and measured admission refuses a request they used to cover. **Migration:** replace an `h3.profile/1:` entry's
  identity with what `aether-probe h3-profile-identity PROFILE.json` prints for the profile it was measured on. That
  is valid only when the profile's content is unchanged (a path-only clone); otherwise re-measure with
  `Scripts/qualify-h3-memory.py`. Code that compares `resourceIdentity` with a stored string needs the new form.

Two tooling changes:
- **New dense language exports attend in float32.** Forge's shared dense exporter promotes Q, K and V to float32 for
  attention and casts the result back; weights and caches stay fp16. It fixes a Qwen3 fp16 argmax flip found during
  the OLMo2 spike ([RCA](../spikes/olmo2-2026-11.md#qwen3-mismatch-rca-and-fix)). Compiled bundles, the published
  Qwen3-0.6B sample included, are unchanged until re-exported; `--attention-precision float16` keeps the old
  arithmetic. Qwen3-VL's blocks keep their qualified path.
- **Xcode 27.2.** CI builds with Xcode 27.2, and `Scripts/check-ci-host.sh` refuses any other Xcode.

## Known limitations

- **One qualified Mac**, and no new iPhone qualification. The spikes are qualified on macOS only.
- **The frozen API is the only compatibility promise.** The H3 products are Preview, and the spike products are
  experimental.
- **H3 (Preview):**
  - Measured admission knows the 0.0.5 final stack (`2a2d5198`) and the 0.0.3 profile on one Mac (M5 Max), and
    refuses other profiles and Macs. 10 s clips and 1280×704 / 704×1280 need a 64 GiB Mac, and 1344×768 / 768×1344
    have no measured entry.
  - Turbo4 has measured admission for memory only, at 960×544 and 544×960 up to 243 frames, and still no CPU
    trajectory gate.
  - The admitted worst case carries the unexplained step-0 transient.
  - At 288×288, block 49 of the first+last trajectory exceeds the 0.02 bar, as the first-only control does on the same
    harness; it is a property of that small canvas, and the bar is qualified at 960×544.
  - FL2VA leaves less room for the prompt, and some first+last requests at the largest canvases can't fit at all.
- **Spikes:**
  - GPT-2 and Phi-2 are base completion models: no chat template, and the chat facade reports `unsupportedTemplate`.
  - OLMo2's extended gate ran a 2,048-token session against its registered 4,096.
  - SD-Turbo runs one fixed 512×512 geometry in float32. It has no catalog integration, lifecycle policy or published
    bundle, and cancellation inside a submitted call and memory pressure are unqualified.
- **Kokoro:** phoneme input only; float32 decoder only.
- **Real-weight qualification is local.** CI covers the weight-free suite, the floor build, the consumer packages,
  the sample app's logic, the controllers' supervision tests and the frozen API; the macOS 15 launch runs on `main`
  and gates the tag.

## Compatibility

The app-facing API frozen in 0.0.4 is unchanged ([API stability](../api-stability.md)). Coming from 0.0.4, see
[source changes and migration](#source-changes-and-migration): every 0.0.4 H3 profile needs the vision overlay for
FL2VA, and stored H3 measured entries need the `h3.profile/2` identity. Everything outside the frozen API may still
change in any 0.0.x release.
