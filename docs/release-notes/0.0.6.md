# AetherKit 0.0.6 — experimental developer preview (draft)

Not released. This draft collects 0.0.6's changes as they merge.

0.0.6 so far:
- **Typed H3 limit refusals.** A request past one of H3's length limits is refused with `H3LimitExceeded`, carrying
  the limit and the request's numbers, instead of an `AetherError` whose message callers had to parse.

The frozen API ([API stability](../api-stability.md)) is unchanged: `H3LimitExceeded` is in `AetherH3`, which isn't
frozen, so the committed baseline in `api/` is still the 0.0.4 baseline. **Outside the frozen API there is still no
compatibility promise in 0.0.x** ([below](#source-changes-and-migration)).

## Install

```swift
.package(url: "https://github.com/bubstackdev/aether-kit", exact: "0.0.6")
```

Building needs Xcode 27.2 (Swift 6.4). See the [README](../../README.md) for the quick starts and the
[H3 guide](../h3-integration.md) for the limits.

## Highlights

- **Typed H3 limit refusals.** `H3LimitExceeded` is a public `Error`, `Sendable` and `Equatable`, and
  `@nonexhaustive`, so a `switch` over it needs `@unknown default`. Its cases:

  | Case | Thrown by | Payload |
  | --- | --- | --- |
  | `promptBytes(limit:bytes:)` | `H3ResourceAdmission.envelope(for:)`, so `H3VideoSession.generate` | The admission's `maximumPromptUTF8Bytes` and the prompt's UTF-8 bytes |
  | `presentationTokens(limit:prompt:keyframes:)` | The profile conditioner's preflight and encode | The profile's text-token limits (`ClosedRange<Int>`), the prompt's tokens, and the tokens the keyframes' labels and vision blocks add (0 for T2VA) |
  | `packedRows(limit:clip:prompt:)` | The profile conditioner's preflight | The denoiser's row limits (`ClosedRange<Int>`), the rows the clip needs without the prompt (target video, audio, the keyframes' condition video and presentation), and the prompt's tokens |

  The split answers the question callers had to guess at: **a size or length that fits no prompt** (`clip >=
  limit.upperBound`, since a prompt has at least one token), such as 1280×704 × 141 first+last, against **a prompt
  that pushes a clip over** (a shorter prompt fits). Likewise, a `presentationTokens` refusal whose `keyframes` alone
  exceed the limit fits no prompt. The message text is kept, and now says how the rows split, but callers switch on
  the case. Other refusals (no measured entry, a canvas without a tower graph, a profile without the vision overlay
  or an audio decoder) stay `AetherError`.

## Source changes and migration

0.0.6 changes no frozen API. These H3 changes affect code outside it:
- **The three length refusals are `H3LimitExceeded`.** They were `AetherError.invalidRequest` (prompt bytes,
  presentation tokens) and `AetherError.unsupported` (packed rows). **Migration:** catch `H3LimitExceeded` before
  `AetherError`, and drop any matching of their text ("H3 prompt exceeds", "H3 presentation has", "H3 clip needs …
  packed rows").
