# AetherKit 0.0.4 — experimental developer preview

Released 2026-11-02.

0.0.4 is the app-readiness release. Its roadmap gated the tag on everything around a model that isn't inference
([roadmap](../roadmap-0.0.4.md#release-gate-app-readiness)):
- **Model preparation:** pinned catalog entries, resumable downloads (including iOS background transfers) and verified
  installation.
- **Typed readiness:** one state per model that an app can show, decided before anything downloads.
- **A managed lifecycle:** idle unload, memory-pressure release and a load gate, for the language facade and the
  generative products.
- **A sample app** that proves them together on a sandboxed Mac and an iPhone, and **an API freeze**: from 0.0.4 the
  app-facing API is frozen for the rest of 0.0.x, and CI enforces it.

Kit now publishes one sample bundle, Qwen3-0.6B, and distributes no other weights. Alongside the gate, the H3 fused
attention spike closed (no re-export needed), and H3 gained per-entry memory bars and the larger-canvas export; its
measured entries come later. Everything in the roadmap's parallel tracks that wasn't merged moved to 0.0.5
([below](#moved-to-005)).

Every model is still checked against independent references computed on the CPU. **Outside the frozen API there is
still no compatibility promise in 0.0.x.**

## Install

```swift
.package(url: "https://github.com/bubstackdev/aether-kit", exact: "0.0.4")
```

See the [README](../../README.md) for the quick starts, the [sample app](../sample-app.md) for the whole flow from
download to chat, and [API stability](../api-stability.md) for what is frozen.

## Highlights

- **Model preparation** ([guide](../model-preparation.md)):
  - **Pinned entries.** A `ModelCatalogEntry` pins every file's path, size and SHA-256, and where to fetch it: HTTPS,
    or a Hugging Face repository at a full commit revision. `aether-probe catalog-entry` writes one for a `language`,
    `kokoro`, `flux2` or `krea` bundle.
  - **Preparation.** `ModelPreparation` checks free space, downloads into a per-installation area kept across launches
    (resuming partial files), installs through the store's hashed install and cleans up. It reports a stream of
    progress events that ends in installed, failed or cancelled.
  - **Transports.** `URLSessionTransport` resumes with HTTP `Range` requests, keeps redirects on HTTPS and forwards the
    app's headers only to the original host; `huggingFaceAuthorization(token:)` sends a token only to huggingface.co.
    `BackgroundTransport` keeps downloads going while an iOS app is suspended.
  - **Hand-off.** `AetherLanguageModel(installation:)` opens a prepared installation and holds its read lease for as
    long as the model, its copies and its sessions exist.
- **Typed readiness** ([guide](../model-readiness.md)): `ModelReadiness` reports `notInstalled`, `installing`,
  `verifying`, `ready`, `unsupported` (OS, platform or memory) or `failed` (with `isRetryable`), as a snapshot and a
  stream, with `prepare()`, `cancel()`, `refresh()` and `uninstall()`. Unsupported is decided before anything
  downloads, from the product's check and the entry's optional `ModelRequirements`. Memory is compared with physical
  memory on a Mac and with the app's memory limit on iOS.
- **Managed lifecycle** ([guide](../model-lifecycle.md)):
  - **Idle unload.** By default a loaded model unloads after 60 s idle on iOS and 5 min on the Mac.
  - **Memory pressure.** Each warning or critical notice releases each idle model once; running requests are never
    cancelled. While pressure is critical, new loads are refused.
  - **Easing critical.** iOS never reports a return to normal after an app's critical notice, so critical eases on a
    normal notice, once the app's available memory has recovered to twice its value at the notice, or 60 s after the
    last critical notice (on a Mac, only once the kernel no longer reads critical).
  - **Per product.** The language facade (Qwen3 and Qwen3-VL) unloads and loads again on the next request; Kokoro
    releases both models and keeps its session usable; Krea and FLUX.2 release the models a session keeps between
    operations; H3 refuses a generation under critical pressure.
- **API freeze** ([API stability](../api-stability.md)): the language facade (`AetherLanguage`, `@AetherGenerable`,
  `@AetherGuide`), preparation and readiness with the catalog entry types (`AetherAssets`), and the lifecycle policy
  and state types (`AetherKit`). CI's **Public API (frozen)** job compares them with the committed baseline in `api/`
  (`Scripts/check-api.sh`, `swift-api-digester`), and **CI passed** requires it. The check fails closed: on a break,
  on a stale baseline, and on a frozen signature that exposes an unfrozen type.
- **Sample app and the published bundle** ([guide](../sample-app.md)): `Examples/SampleApp` downloads Qwen3-0.6B from
  [`aether-models/aether-kit-qwen3-0.6b`](https://huggingface.co/aether-models/aether-kit-qwen3-0.6b) (converted from
  `Qwen/Qwen3-0.6B` under Apache-2.0; `mac/` and `ios/` bundles) through `ModelPreparation`. It shows the model's
  readiness, streams a chat, runs one structured-output request and shows the lifecycle live.
- **H3:**
  - **Fused attention, no re-export** ([spike](../spikes/h3-attention-2026-10.md)). The qualified body graph already
    exports `F.scaled_dot_product_attention` as Core AI's SDPA composite, and the GPU runs it fused: no score tensor is
    allocated between calls, it runs at 44–56 TFLOPS, and it's 2.8× faster than explicit attention at 4,096 rows. H3's
    profile identity and qualification evidence stand.
  - **Per-entry memory bars** (decided 2026-10-29). An identity may carry several measured entries, each with its
    canvases, maximum frames, optional tasks and its own bar: 18 GiB for today's region, or 24 GiB beyond 960×544's
    pixels or 124 frames, used only with at least 64 GiB of physical memory. A request is held to one covering
    envelope. The bundled 0.0.3 entry decodes with its 18 GiB bar and reservations unchanged.
  - **Larger-canvas export** ([section](../h3-integration.md#larger-canvas-1280704-and-the-10-s-clip-004-in-progress)).
    An overlay profile adds tails for 1280×704, 704×1280, 1344×768 and 768×1344 and fixed audio decoders for 141 and
    243 frames, each byte-identical to the pipeline on CPU. Measured on this Mac (busy host), T2VA 1280×704×141 and
    960×544×243 run with worst cases of 21.78 and 21.76 GiB. **No larger-canvas entry is bundled in 0.0.4:** entries
    are measured under the final overlay stack, which moved to 0.0.5.
- **Verified-hash cache:** opening a bundle no longer re-hashes an unchanged multi-GB file. Language, Krea and H3
  checks remember a passing SHA-256 by file identity (local APFS and HFS+ only), always reading the file or descriptor
  whose identity they record. Measured warm on an M5 Max: the Qwen3-VL-4B open went from 4.1 s to 1.3–1.5 s, Krea 2's
  `verify()` from 2.7–3.2 s to 0.01 s, and H3's first weight load from 13.4 s to 2.5 s. The store is per user and
  unsigned, inside the same trust boundary as the manifests ([architecture](../architecture.md#verified-hash-cache)).
- **CI:** the floor consumer's launch job runs on `macos-15`, because GitHub retires `macos-14` on 2026-11-02. macOS 15
  has no CoreAI either, so the job still requires a weak CoreAI link and `unsupportedOS`; macOS 14 itself is covered
  by the floor build only ([deployment floor](../deployment-floor.md)).

## Breaking changes and migration

- **Growable enums are `@nonexhaustive`** (SE-0487). Code outside the package that switches over one exhaustively no
  longer compiles in Swift 6 mode (a warning in Swift 5 mode). The enums: `AetherLanguageError`,
  `AetherLanguageModel.UnavailableReason`, `AetherStopReason`, `AetherTranscript.Entry`,
  `AetherGenerationOptions.Reasoning`, `AetherGenerationOptions.SamplingMode.Kind`, `PreparationError`,
  `PreparationEvent`, `ModelSource`, `ModelReadiness.State`, `.Progress.Phase`, `.Unsupported`, `.Failure`,
  `ModelLifecycleState`, `ModelUnloadReason`, `AssetStoreError` and `LanguageModelManifest.Platform`.
  **Migration:** add `@unknown default:` to each such `switch`, or a catch-all pattern such as
  `case .unavailable(let reason):`.
- **Lifecycle defaults:**
  - Models now unload after sitting idle by default: the language facade, Kokoro (its prewarmed bucket
    specializations go with it, so the next utterance specializes again), and the models Krea and FLUX.2 sessions keep
    in either residency mode. The next request pays the load again. **Migration:** pass `lifecycle: .manual` to keep
    0.0.3's behaviour.
  - Under critical memory pressure a new load is refused: `AetherError.memoryPressure`, or
    `AetherLanguageError.insufficientMemory` from the language facade. `AetherError` gains `memoryPressure`, so an
    exhaustive switch over it needs a new case.
  - `AetherLanguageModel.prewarm()` now waits its turn in the request slot.
- **H3 measured admission covers less**
  ([guide](../h3-integration.md#memory-bars-beyond-960544-and-124-frames-decided-2026-10-29)):
  - A canvas must now fit inside a listed canvas of the same orientation. Before, any canvas up to the entry's pixel
    count was admitted, so the bundled 0.0.3 entry now refuses canvases such as 1024×480, 640×800 and 576×576. An
    uncovered request is refused naming the nearest envelope. **Migration:** request a listed canvas of the entry, or
    a canvas of the same orientation that fits inside one.
  - `H3MeasuredResources.bundled(executionIdentity:deviceArchitecture:)` now throws when several entries are recorded
    (counted before the memory filter). **Migration:** use the new `bundledEntries`, `bundledAdmission` or
    `admission(entries:)`.

## Known limitations

- **One qualified Mac.** On iOS, the 0.0.4 gate pieces are qualified on an iPhone19,4; model coverage is as in 0.0.3:
  Kokoro (two iPhones) and the Qwen3-0.6B.
- **The frozen API is the only compatibility promise.** Everything outside [API stability](../api-stability.md)'s
  list may still change in any 0.0.x release. The freeze is source compatibility, not ABI stability.
- **One published bundle.** Kit publishes Qwen3-0.6B only; apps bring every other model themselves, through catalog
  entries they pin.
- **Readiness checks:** Kit ships `ModelRuntimeCheck.language`; for other products the app writes its own check, or
  uses `ModelRuntimeCheck.none`, which checks only the entry's requirements
  ([other products](../model-readiness.md#for-other-products)).
- **Lifecycle:** a reload after an idle unload pays the load again, and Kokoro specializes its buckets again. A busy
  model releases only when its request ends.
- **Language:** the memory budget is still a workaround for Core AI retention.
- **Qwen3-VL:** still no iPhone run. The VL-2B failed while opening at the default limits on an iPhone18,2 in 0.0.3;
  the extended-virtual-addressing entitlement and an open-time check that counts mapped bytes moved to 0.0.5.
- **H3 (Preview):**
  - Measured admission bundles one entry, for one profile on one Mac (`5af39db5…`, Turbo8, M5 Max), and refuses
    others. It now covers only canvases that fit inside a listed one of the same orientation.
  - Turbo4 stays outside measured admission; its qualification moved to 0.0.5.
  - **FL2VA conditioning differs from upstream** (found 2026-10-29, in 0.0.3): Kit's conditioner sees the prompt text
    alone, while upstream also presents each keyframe as Qwen3-VL image tokens. The keyframe still conditions the
    render through its anchored latents. The fix moved to 0.0.5
    ([known deviation](../h3-integration.md#known-deviation-fl2va-conditioner-presentation-found-2026-10-29)).
  - `H3VideoRequest.lastFrame` is still refused.
  - The admitted worst case carries an unexplained step-0 transient, and profile paths relative to `bundle.json` are
    a follow-up.
- **Kokoro:** phoneme input only; float32 decoder only.
- **Real-weight qualification is local.** CI covers the weight-free suite, the floor build and launch, the consumer
  packages, the sample app's logic and the frozen API.

## Compatibility

**From 0.0.4, the app-facing API is frozen for the rest of 0.0.x** ([API stability](../api-stability.md)). Later 0.0.x
releases may add to it (types, members, defaulted parameters, cases of `@nonexhaustive` enums, conformances) and
deprecate a declaration, which then stays until 0.1. They may not remove, rename or retype a frozen declaration. CI
enforces this against the committed baseline in `api/`. Everything else may still change in any 0.0.x release.

Coming from 0.0.3, see [breaking changes and migration](#breaking-changes-and-migration): `@unknown default` for the
growable enums, `lifecycle: .manual` for 0.0.3's residency, and the narrower H3 admission coverage. The bundled 0.0.3
H3 entry decodes with its bar and reservations unchanged.

## Moved to 0.0.5

By the roadmap's rule, everything in a parallel track that wasn't merged by the tag moves to 0.0.5
([0.0.4 roadmap](../roadmap-0.0.4.md#moved-to-005)):
- **H3 FL2VA conditioner presentation:** the fix for the known deviation above.
- **H3 last-frame conditioning** ([draft PR #78](https://github.com/bubstackdev/aether-kit/pull/78)).
- **H3 larger-canvas measurements,** and entries bundled under the final overlay stack
  ([draft PR #81](https://github.com/bubstackdev/aether-kit/pull/81)). The export work from #77 shipped.
- **H3 Turbo4 qualification.**
- **Products from 0.0.3 spikes:** TripoSR (image to 3D), ACE-Step 1.5 (text to music) and Granite 4.0-H (hybrid
  language, with the start-scalar dynamic-q re-qualification).
- **The iOS open-time memory check,** with the VL-2B run under the extended-virtual-addressing entitlement.
- **FLUX.2 on iOS.**
- **The MLX backend** for older OSes.
- **Shared declared residency** ([proposal](../shared-residency-proposal.md)).
- **Exporter safety checks,** the Core AI retention mitigations and the Kokoro fp16 decoder's float32 style linears.
- **Spikes:** quantization, and one length input for the dense language contracts.
