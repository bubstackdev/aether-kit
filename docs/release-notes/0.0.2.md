# AetherKit 0.0.2 — experimental developer preview

Released 2026-10-27.

0.0.2 adds FLUX.2 [klein] image generation and editing, Kokoro speech synthesis, Qwen3-VL image input and a model's own chat template to the language runtime, a fixed-shape language decode contract, and H3 schema-3 graph, trajectory and memory gates under an 18 GiB bar (H3 stays experimental). It also adds one shared GPU lease and opt-in GPU admission for every session. Every model is checked against independent references computed on the CPU (float32; H3's oracle runs the original bf16 modules), and the Python tooling that exports models and computes those references now lives in this repository, in locked environments. **There is still no API compatibility promise in 0.0.x, and no model weights are distributed.**

## Install

```swift
.package(url: "https://github.com/bubstackdev/aether-kit", exact: "0.0.2")
```

The repository moved from `atelier-private-dev/aether-kit` to `bubstackdev/aether-kit`. See the [README](../../README.md) for the quick starts.

## Highlights

- **FLUX.2 [klein] 4B:** four-step generation without guidance; one- and two-reference editing; prepared prompts and references; balanced or resident residency; cancellation and awaited `unload()`. Export the bundle with `Forge/flux2`.
- **Kokoro speech:** segment-by-segment delivery, exact length buckets so the GPU specializes once per bucket, a frame cap of 1024 on macOS and 512 on iOS, and float32 only. The SDK contains no G2P, which keeps GPL espeak-ng out of the dependency graph.
- **Language:**
  - The bucketed step contract keeps input shapes in a fixed set: one 64-token prefill width, with caches grown in 256-row steps. It is the default for new exports.
  - A memory budget bounds a Core AI retention bug (below).
  - `AetherLanguageTokenizers` renders each model's own chat template.
  - Qualified on Qwen3-0.6B, an abliterated Qwen3-4B-Instruct-2507 (Atelier's writer), Qwen3-VL-2B, and an abliterated Qwen3-VL-4B (Atelier's describer).
- **Qwen3-VL image input:** images snap to five fixed patch grids, each encoded by a static function. A dynamic-shape encoder intermittently computed wrong outputs on the GPU, so it isn't used.
- **H3 schema-3:**
  - Graph and trajectory gates at 960×544 for text-to-video+audio and first-frame-to-video+audio.
  - A tiled first-frame encoder cuts that stage from 27.3 to 2.05 GiB.
  - Measured admission refuses a render before any stage loads unless its largest stage fits.
  - Denoiser blocks chain on the device.
- **Shared GPU lease:** Kit's tools and native suites take an Atelier-compatible cross-process lease, and every session accepts an optional `gpu:` admission owner.
- **Forge:**
  - Two locked Python environments, `Forge/` and `Forge/h3-oracle`, resolve from public sources.
  - Exporters and references no longer depend on any interpreter outside this repository.
  - Re-runs reproduce recorded outputs byte for byte.

## Core AI retention and the memory budget

Core AI keeps Metal allocations each time a reshape-enabled function changes input shape, until the model is released. Every language request changes shape (prefill chunks, then single-token steps), so warm requests kept growing memory. `LanguageGenerationSession` now measures each request's growth. Once the growth retained since the model loaded passes `memoryGrowthBudgetBytes` (2 GiB by default), it reloads the model between requests. It reloads at idle when it can, otherwise in front of the next request. The KV state is Kit's own and is unaffected. This is a workaround, removable once Core AI stops retaining memory. See [native memory retention](../language-generation.md#native-memory-retention).

## Known limitations

- **Single qualified Mac;** iOS is unqualified except Kokoro on one iPhone.
- **No hosted assets** or download transport, and no published Krea bundle specification.
- **Language:** the memory budget is a workaround for Core AI retention, and a reload costs a model load. Bucketed decode steps cost somewhat more than running-contract steps.
- **Qwen3-VL:**
  - Core AI wires the decoder's text weights twice, once each for text-only and image prompts. A one-image 4B request wires about 16 GiB.
  - Opening the 4B decoder reads its 22.5 GiB compiled file into the page cache.
  - Images stretch by up to about 15% to fit a grid; panoramas or tall strips beyond 16:9 stretch more.
  - One image per prompt, and macOS only.
- **H3:** still experimental. Media audit and per-stage lifecycle qualification are pending. The bar applies only to sessions created with measured admission, and measured admission knows one profile on one Mac (`c49d8dbf`, Turbo8, M5 Max); others are refused. The qualified profile is a local export outside this repository.
- **Kokoro:**
  - Phoneme input only.
  - Bucket 2048 holds about 8 GB of Metal until unload.
  - The duration graph runs on the CPU.
  - Only the float32 decoder is supported.
- **FLUX.2:**
  - The bundle's `chat_template.jinja` isn't hashed.
  - Reference pictures are bounded by their longest side (512), not by area as in Diffusers.
- **GPU lease:** pid-less leases aren't reclaimed.
- **Real-weight qualification is local.** CI covers the weight-free suite and consumer packages only.
